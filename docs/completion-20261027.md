## 操作后的业务健康验证

新提交的站点启动、停止、重启及应用池启动、停止、回收，在原编号确认成功后，后台自动检查同服务器、受影响站点或应用下**已经启用**的健康检查。无需保持浏览器打开。没有匹配的已启用检查时明确跳过，不临时启用检查、不扩展到全服务器。

跟进结果持久化到原 Console 任务的 `healthFollowUp`，工作台和历史详情独立显示检查范围、状态、时间、HTTP 状态及耗时。业务异常不改变 IIS 操作本身的执行结果。停止成功后业务不可用是实际探测状态，不等同于停止失败。

每批最多 20 项、共用 60 秒预算；手动、定时与跟进检查共享并发限制。旧记录无标记不补跑，原编号查询不重复触发，进程重启时已开始但未完成的批次标记未知，不重放。原请求、任务编号、指纹和历史平台字段保持原契约。详细边界见 [操作后检查说明](operation-health-follow-up.md)。

## FREB 请求级诊断

“故障诊断”新增 FREB 区，按站点/HTTP 状态筛选，逐条展开时间、方法、HTTP/子状态、失败模块、通知阶段及有限管线事件；支持脱敏 JSON 导出。FREB 与普通资源诊断分别读取，旧 Agent 提示升级，部分文件失败不遮蔽其它可用记录。

只读取 IIS 当前配置目录中已生成的跟踪，禁止原始 URL、请求头、正文、原 XML 或磁盘路径返回浏览器。显示编号为本进程的匿名关联标识，不是磁盘文件名；操作员可按站点、时间和状态在服务器核对原文件。安全 XML 解析、文件身份与链接检查、时间窗口和采样预算见 [FREB 说明](freb-diagnostics.md)。

服务器须由操作员安装 IIS Tracing 角色服务、为所需站点开启失败请求跟踪并配置规则；本工具不会自动执行这些生产设置。配置后由 IIS 在符合规则的真实请求发生时生成文件，刷新即可读取，不需再次更新 Agent。活跃写入中的 XML 会安全拒绝，稍后读取完整记录。
