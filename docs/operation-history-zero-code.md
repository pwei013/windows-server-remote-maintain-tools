## 平台结构

在“windows服务器远程管理”的默认分组新增普通表单“操作记录”，包含操作编号（唯一）、服务器编号、操作类型、操作目标、操作状态、操作人编号、操作人姓名、来源IP、提交时间、更新时间、请求指纹和错误代码。布局分为“操作信息”“身份与追溯”，全部字段已加入默认列表；三个接口为 `QueryOperationHistory`、`CreateOperationHistory`、`UpdateOperationHistory`。

平台设计元数据、布局、列表和接口均完成发布并独立回读；实际字段编码与发布证据见 [平台契约](operation-history-platform-contract.json)。这是平台 API 层证据，本次没有直接访问物理数据库，也没有调用真实新增/更新接口写测试业务数据。

## 接入与保存

生产默认启用操作记录持久化，复用现有 `Console:SiteAnnotations` 的应用连接及当前操作人的应用用户 Token，连接与站点标注功能的启用开关相互独立；不新增密钥或密码配置。可选设置如下（缺省值与示例一致）：

```json
{
  "Console": {
    "OperationHistory": {
      "Enabled": true,
      "SyncIntervalSeconds": 10
    }
  }
}
```

开发配置显式关闭此功能和用户认证；开发模拟记录不会伪造真实用户。生产仍强制登录。现场连接不完整时原登录提示保持有效，不能通过关闭用户认证绕过配置。

本地账本继续负责接单去重、查询及恢复。Console 先落盘本地操作意向，再向 Agent 提交一次，随后同步平台。平台仅保存上述审计信息，不上传请求参数、Agent Token、用户 Token、密码或连接配置。操作记录页仍查询本地账本；平台副本可在零代码“操作记录”列表查看，本次不提供从平台重建本地执行账本的功能。

平台保存独立于执行状态：`synced` 显示“已保存”，`pending` 显示“待保存”，`unknown` 显示“待核对”，`notConfigured` 显示“未启用”。平台连接故障不会让已经提交的 IIS 操作重放；只有独立查询的全部记录值匹配，才显示“已保存”。平台新增前按原操作编号查重，更新只使用读回的原主键，并且只修改状态、更新时间及错误代码。

保存前把本次快照指纹写入本地回执，成功和异常响应之后都独立读回。响应丢失、读回失败或值不匹配时保留未知回执，不自动重发该次新增/更新。后续只读核对证明原快照已提交，才可以更新到新的状态；原记录缺失、主键变化、归属或已确认值漂移时报告冲突。平台查询每页 200 条、最多 10000 条，必要时逐页精确匹配编号；总数漂移、重复页、字段缺失、超限等会报告不可可靠读取，不采用截断数据。

后台每 10 秒查询未完成的 Agent 任务并补同步待保存记录，不执行 IIS 写入。相同 Agent 内容不会反复改写时间或平台记录。后台复用原操作人的有效内存会话；退出、Token 过期或 Console 重启后暂停该人的补同步，原操作人重新登录后继续。Token 不写入文件。已保存的终态记录不持续轮询平台。

“待核对”时按原编号检查零代码记录和本地回执；不要删除本地记录、换编号提交 IIS 操作或直接重发平台写入。需要人工恢复时应先判定原写入是否发生；本次不提供自动解除未知状态的写操作。
