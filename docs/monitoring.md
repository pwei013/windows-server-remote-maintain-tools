# 服务器总览、业务健康检查与证书预警

首期源码增加 `/overview.html`，可从顶部“服务器总览”进入。页面继续使用现有应用用户登录、会话和 Agent 通信认证。2026-10-27 起，新提交的 IIS 生命周期操作成功后会自动跟进已启用且属于影响范围的检查，并在原操作中单独记录业务结果；不改变原操作编号、预检查或 IIS 执行状态。详见 [操作后健康验证](operation-health-follow-up.md)。总览刷新、手动和定时检查仍按各自入口执行。

## 总览与搜索

页面集中显示已配置服务器的连接状态、站点、应用池、可管理 Windows 服务数量，以及业务检查异常和证书预警。点击服务器或资源链接可回到对应管理工作台。

全局搜索支持服务器编号、名称、主机、项目分组、环境、站点名称、应用路径、域名和应用物理目录；按项目、环境、连接状态进一步筛选。搜索结果只包含本次已成功读取的资源；模块读取失败会在服务器卡片中提示，不能把缺少数据当作没有资源。总览不额外读取站点/应用的零代码别名与标签。

`online` 表示此次全部模块读取成功，`partial` 表示部分模块失败，`offline` 表示所有模块均未取得数据。服务器信息、IIS 快照、应用拓扑、服务和证书分别读取；证书失败不会使已成功取得的 IIS 数据消失。连接状态表示管理数据是否可读取，不表示业务站点健康。

“刷新总览”只重新读取管理数据和已保存的检查结果，不调用业务检查地址。可勾选“每 30 秒刷新”；页面不可见时暂停自动刷新。总览资源有服务端缓存，默认 15 秒，显示的采集时间用于判断数据新鲜度。

## 可选配置

旧 Console 配置无需新增字段即可使用默认监控设置。若需要项目/环境分类，仅向已有 `Console:Servers` 的对应服务器对象合并以下两个字段，保留该对象原有的编号、名称、连接及认证字段，不替换整个服务器数组：

```json
{
  "Group": "示例项目",
  "Environment": "测试"
}
```

两字段均可省略，默认空字符串；最多 64 个字符，不接受控制字符。页面将空值显示为“未分组”或“未设置”。这些启动配置更改后需要重启 Console。

可选监控设置位于 `Console:Monitoring`：

```json
{
  "Console": {
    "Monitoring": {
      "DataDirectory": "data/monitoring",
      "OverviewCacheSeconds": 15
    }
  }
}
```

该片段用于合并已有配置，不是完整可运行配置。`OverviewCacheSeconds` 允许 5–120 秒；相对数据目录以 Console 内容根目录为基准。默认健康检查文件为 `data/monitoring/health-checks.json`，包含配置、最近结果及最近成功时间。目录应保留在站点静态资源目录之外，并由 Console 服务身份持有必要读写权限；不要在文件中添加凭据或秘密。

## 配置并运行业务健康检查

1. 在总览“业务健康检查”点击“新增检查”，选择服务器、站点和根应用或子应用。
2. 填写该应用的专用只读检查地址，例如合成示例 `https://example.invalid/api/health`；该地址实际使用时必须属于所选站点的当前绑定及 `/api` 应用。
3. 设置期望 HTTP 状态码、超时和检查间隔。期望状态码为 200–299 中的一个具体值，默认 200；超时 1–15 秒，默认 5 秒；间隔 30–3600 秒，默认 60 秒。
4. 新增时默认停用。保存只会请求 Agent 验证当前站点、应用和绑定，不访问业务检查地址。勾选“启用定时检查”并保存后，Console 服务端开始调度，无需保持浏览器打开；首轮可能在保存后不久执行。
5. 已启用的检查可以“立即检查”；停用项不能手动运行。编辑保存可停用后续检查，删除仅删除检查配置，不删除 IIS 站点或应用。

每个服务器下的站点/应用配置一项检查，最多 200 项。后台每 5 秒查看到期项，按上次完成时间加配置间隔安排下次检查，实际开始时间还受队列与请求耗时影响；不是精确到秒的定时承诺。同一检查不会同时重复执行，后台检查与 Agent 探测各有最多 4 个并发限制。停用不撤销已发出的只读 HTTP 请求；编辑或停用后的配置不会被旧版本请求结果覆盖。

检查由对应 Agent 在服务器本机执行，不由浏览器发起。每次执行前重新读取 IIS 拓扑：

- 地址的协议、端口和主机须匹配所选站点的当前 HTTP/HTTPS 绑定，URL 路径须属于所选的最具体应用；选根应用不能探测落入另一子应用的路径。
- 仅连接当前服务器的绑定地址。IP 地址形式的 URL 连接同一本机 IP；显式 IP 绑定须与之匹配，IPv4/IPv6 通配绑定遵循对应地址族。域名绑定保留原主机用于 HTTP Host 和 HTTPS SNI，连接固定到相应本机地址。
- 站点为 `Stopped` 时不发送 HTTP，返回 `HEALTH_SITE_STOPPED`；`Starting`、`Stopping`、`Unknown` 等非 `Started` 状态返回 `HEALTH_TARGET_NOT_RUNNING`。仍可为停止站点保存合法检查配置。
- 只发送 GET，不跟随重定向，不使用代理、Cookie、登录凭据或 Agent 访问令牌，不读取或返回业务响应正文；HTTPS 使用正常证书验证，不跳过证书错误。
- 不接受 URL 账号、查询参数、片段、控制字符、模糊编码/路径或管理保留端口。检查地址本身应保证只读，不使用会发消息、付款、回调或修改数据的业务接口。

结果分别表示：

| `state` | 含义 |
|---|---|
| `healthy` | 实际 HTTP 状态码等于配置的期望值 |
| `unhealthy` | 已收到 HTTP 响应，但状态码不符；重定向也不会自动跟随 |
| `unavailable` | 目标不运行、绑定变化、连接、TLS 或超时等原因导致无法完成检查 |
| `unsupported` | 当前 Agent 不支持健康检查，需要升级 |
| `simulation` | 开发模拟结果，没有访问真实业务地址，不计为真实成功 |

最近成功时间仅在 `healthy` 时更新。HTTP 成功只说明该检查地址满足所配置条件，覆盖哪些依赖由检查地址自身决定；IIS 站点、应用池或服务的运行状态，以及原启停任务结果仍单独显示。健康检查不会改变 IIS/服务状态，也不触发自动重启。

旧 Agent 仍可通过原有接口提供总览数据；新增健康检查的保存会提示升级 Agent，不使原有 IIS/服务管理入口失效。旧 Agent 原本不具备的其它读取模块仍按该模块的实际能力显示失败提示。

## 证书预警

证书数据来自 Agent 的现有证书接口，结合成功取得的站点绑定显示关联站点、域名和端口。默认仅显示预警，也可切换全部证书或具体等级。本期提供页面提示，不自动续签、导入或替换证书，也不发送外部通知。

| `severity` | 判定条件 |
|---|---|
| `missing` | HTTPS 绑定引用的证书指纹不在本次成功读取的证书清单中 |
| `notYetValid` | 证书开始生效时间晚于当前时间 |
| `expired` | 已到或超过证书到期时刻 |
| `critical` | 尚有效，剩余时间大于 0 且不超过 7 天 |
| `warning` | 剩余时间大于 7 天且不超过 15 天 |
| `notice` | 剩余时间大于 15 天且不超过 30 天 |
| `normal` | 剩余时间大于 30 天 |

等级按实际剩余时长计算，恰好 7、15、30 天分别进入 `critical`、`warning`、`notice`；剩余天数用向上取整展示，不能仅凭显示整数判断是否已过期。未生效优先于到期分级。私钥是否存在另行显示，不等于已验证实际可用。

证书读取失败时显示模块错误，不把读取失败推断为证书缺失；站点/拓扑读取失败时，证书关联信息可能不完整。

## 并发、保存异常与恢复

健康检查配置使用不透明 `revision`；编辑和删除须携带最近读到的值。`HEALTH_CONFIG_CONFLICT` 表示配置已有变化，应刷新、核对后重新编辑，不覆盖别人修改。服务端的配置保存、删除、结果落盘会核对磁盘文件哈希，阻止覆盖运行期间被外部修改的文件。

`HEALTH_STORE_CHANGED`、`HEALTH_STORE_UNVERIFIED` 或 `HEALTH_STORE_UNAVAILABLE` 表示文件漂移、写入结果无法确认，或文件损坏/无法可靠读取。页面和后台停止相关配置写入/检查并给出错误，总览其它模块继续显示。应先只读核对文件内容、版本、权限及实际配置状态，保留原文件，解决原因后再由操作员重启 Console；不要删除文件掩盖问题，也不要因超时自动重放保存或删除请求。外部修改是在后续持久化检查时发现，不保证只读查询立即检测到。

浏览器未收到保存/删除响应时，应关闭弹窗并刷新核对已持久化状态；前端不会自动重复 POST。服务端在文件原子替换后独立读回核验，前端收到成功响应后才更新列表。结果无法确认时先核对，不能把传输失败等同于配置未发生变化。

新增路由、请求字段和错误码见 [API 契约](api.md#服务器总览与健康检查)。浏览器接口继续要求现有应用用户会话；POST 继续要求同源与 CSRF 校验。健康检查配置日志仅记录检查编号、服务器编号和启用状态，不记录检查正文或认证信息。
