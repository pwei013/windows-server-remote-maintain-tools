## 服务器调用配置

按用户要求提供 [空值模板](config/站点标注-零代码配置模板.json)。默认 `Enabled=false`，配置缺省仍关闭；没有调用连接时返回明确的未配置状态。模板不包含真实凭据，也不复用 Codex MCP 登录令牌。

人工将模板中的 `Console:SiteAnnotations` 节点合并进 Console 的受限 `appsettings.Local.json`，保留该文件中原有服务器、Token、证书和其他配置。按平台实际调用配置填写以下值，全部完成后设 `Enabled=true`，重启 Console 服务使启动配置生效。

| 配置 | 含义 |
| --- | --- |
| `ApplicationId` | 已绑定的设计应用 1001，不能改为其他应用套用此字段编码 |
| `OpenApiBaseUrl` | 平台提供的 HTTPS OpenAPI 路径前缀，包含 `/openApi` 等实际前缀，不包含方法名和调用 AppID；不允许用户信息、查询串或 fragment |
| `OpenApiAppId` | 平台运行时提供的调用 AppID，按原值填写；不能仅凭设计应用编号推断 |
| `PublicKeyBase64` | 直接填写平台 RSA 公钥的 Base64 字符串，支持 DER SPKI 和 PKCS#1；不填写文件路径或 PEM 头尾，不使用私钥 |
| `TimeoutSeconds` | 1–120 秒，默认 30；覆盖响应正文和一次完整分页读取 |

公钥现在由 `Console:SiteAnnotations:PublicKeyBase64` 直接读取，不再读取公钥文件。已有配置的 `PublicKeyFile` 需替换为新字段，填入真实平台公钥的完整 Base64 字符串；允许复制时带有空白换行，启用时限制最多 8192 个字符并在启动时校验公钥。缺失、无效、私钥或多余 DER 数据均拒绝启用，只输出固定状态码。更改后重启 Console 管理服务生效，已交付的 1.0.3.0 包保留旧配置契约，使用新字段需更新包含本次改动的 Console。

## 保存和身份约定

标注按 Console 配置服务器编号、IIS 站点编号和原名称关联。保持服务器配置编号稳定；改变编号会使用新的标注范围。IIS 名称或编号变化后，不会把旧标注自动应用到新的组合。相同编号和原名称的重建站点具有同一组合，需人工核对标注归属。

站点下的子应用也可独立设置别名和标签，使用同一编辑面板并显示所属站点和原应用路径。原路径保留在子表中，搜索和标签筛选包含应用标注。原站点唯一键仍为 64 字符；子应用唯一键为该站点键加上 `[服务器编号, 站点编号, 原站点名称, 原应用路径]` JSON 的 SHA256，共 128 字符，满足现有唯一字段上限，无需新增平台字段或接口。应用路径由最新 Agent 拓扑与该键匹配恢复；保存前再次检查身份，已删除或改名的应用标注不会出现在列表中，同路径应用按服务器及站点隔离。根应用 `/` 沿用站点标注。

本次仅需更新 Console，Agent 已支持 `site-topology` 时无需改动；原标注连接配置继续使用。存在子应用标注后，旧 Console 的 64 字符键校验无法读取该服务器标注列表，回退前须评估这些新记录，不能直接降级宣称兼容。应用路径相同的重建对象仍具有同一标识，需人工核对归属。本地验证使用内存和合成平台响应，不写真实零代码数据；真实持久化和 Windows/IIS 环境由人工验收。

版本由持久化记录、值和修改时间生成，Console 在保存前核对并在同一实例内串行保存；平台的修改接口不支持条件更新，所以该检查不保证多个 Console 或平台直接编辑同时发生时的原子比较更新。运行时使用一个 Console 作为标注写入入口，避免同时直接修改同一条平台记录。

发生超时或不确定结果，只尝试一次写入，随后只读查询；仅值完全匹配才确认成功。页面保留草稿，并阻止自动重提交；人工先核对平台是否完成该次保存，再决定是否读取最新版本进行新的保存。首次保存全空值创建可回读记录；再次保存相同内容不会重复写入。
