# Agent 服务卸载

安装 EXE 1.0.5.0 增加 Agent 服务卸载入口，用于移除固定的 `IISManager.Agent` Windows 服务注册。配置、程序、日志、任务账本、安装归属记录及原回执全部保留，防火墙规则、证书、私钥授权和账号保持原样；受管 IIS 站点、应用程序、虚拟目录、应用池及其他 Windows 服务不作修改。

## 操作步骤

1. 将完整安装包复制到目标 Windows Server 的站点外运维目录，由操作员打开 `IISManager.Setup.exe` 并响应管理员授权。
2. 保留组件 **Agent**，选择已有 Agent 的实际程序目录，点击 **卸载 Agent（保留程序、配置与数据）…**。自定义路径可在 Windows 服务 `IISManager.Agent` 的属性中核对。
3. 点击 **只读核对 Agent**，检查显示的服务状态、实际服务身份、程序目录、数据目录和保留范围。此步骤不停止服务；有任务处于排队、执行中或结果未知时拒绝卸载，先只读核实原操作编号。
4. 勾选确认，再点击 **停止并卸载 Agent 服务**。执行时再次核对审阅指纹，在同一服务句柄中核实身份与入口后停止服务，独占现有账本锁并再次检查任务，再移除服务注册。
5. 等待结果。只有独立读回服务已不存在才显示卸载成功；保留卸载回执。卸载后 Console 无法连接此 Agent，受管网站和应用池不因此停止。

本功能保留全部文件与权限，不自动清理程序目录、数据、遗留防火墙规则或证书。若以后重新安装，使用新的专用程序目录和独立数据目录，避免将旧账本或归属记录当作新安装使用；需要恢复旧实例时先由操作员根据保留回执与最新账本制定恢复方案。

## 核对边界

卸载核对不依赖内嵌载荷版本或 TLS 证书是否有效，也不要求当前 DLL 仍匹配旧安装归属中的运行哈希，因此支持正常手工增量更新后的实例。完整归属记录必须为完成状态；无归属记录的手工实例须满足固定服务名称、精确的 Production 入口参数、可信程序与配置文件、Windows 模式、可证明的实际账本来源和已存在的 `.owner.lock` 等条件。

配置缺失、环境覆盖、未完成安装、非标准服务入口、目录或权限无法核实、服务过渡状态及未完成任务均会阻止自动卸载。数据目录允许已核实的实际服务身份权限，审阅指纹绑定目录及锁文件的真实磁盘身份；执行固定路径后重新核对，停止后再核对，防止审阅期间同名目录被替换。

卸载目录句柄额外请求 `FILE_LIST_DIRECTORY` 并拒绝共享删除，锁文件在服务运行时只采集元数据身份、停止后再取得内容独占锁。该实现依据 [Microsoft 文件共享检查规范](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/8c0e3f4f-0729-49f4-a14d-7f7add593819)收紧，原安装与更新路径的句柄参数保持原样；真实 Windows 句柄、权限和卸载行为仍需实机验收。

服务停止失败、删除超时或仅进入“标记删除”状态时，结果记录为部分完成或未知，不自动重放、回滚或重新启动服务。保留全部文件与卸载回执，先只读核实实际 Windows 服务状态；不要因界面超时推断服务未删除。

## 验证边界

跨平台核心测试覆盖固定服务范围、审阅漂移、任务终态、停止/锁定/核对/删除顺序、失败不重放及取消时机。Windows 目标 EXE 的发布、内嵌载荷和文件完整性检查不能代替 Windows 图形启动、SCM、ACL、真实新装/更新/卸载验收；实际安装和卸载始终由人工操作员在目标服务器执行。
